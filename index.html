Funis de venda

Seis funis.
Preço e consciência escolhem.

As taxas são referências de mercado para o primeiro teste. Depois quem manda é o dado da conta.

01Perpétuo low ticket
Anúncio→Página de vendas→Checkout + bump→Upsell→Downsell
Quando
Produto de R$ 27 a 197, público consciente do problema.
Métrica
CPA contra o ticket médio do funil, não contra o preço do front.
Referência
Página 1–3% · bump 20–40% · upsell 5–15%.
02VSL
Anúncio→Vídeo de vendas→Checkout→Upsell
Quando
Oferta que precisa de explicação ou de mecanismo novo.
Métrica
Retenção até o pitch e conversão de quem viu o pitch.
Referência
Retenção até o pitch 10–25% · página 1–3%.
03Lançamento
Captação→Aquecimento→Carrinho aberto→Fechamento
Quando
Produto core com público frio e autoridade em construção.
Métrica
Custo por lead qualificado e conversão da lista.
Referência
Captura 25–45% · lista para venda 1–3%.
04Live ou webinar
Anúncio→Inscrição→Grupo e lembretes→Live com oferta→Replay
Quando
Ticket médio a alto. Live paga de R$ 27 a 97 filtra curioso e paga o tráfego.
Métrica
Comparecimento e conversão de quem ficou até a oferta.
Referência
Comparecimento gratuito 20–35% · pago 50–70%.
05Aplicação high ticket
Anúncio→Formulário de aplicação→Qualificação→Call→Fechamento
Quando
Mentoria, imersão ou consultoria de R$ 3.000 ou mais.
Métrica
Custo por call qualificada e fechamento na call.
Referência
Aplicação para call 30–50% · call para venda 15–30%.
06Serviço com WhatsApp e CRM
Anúncio de mensagem→WhatsApp→Agendou→Compareceu→Fechou
Quando
Clínicas e escolas. É o funil do kit dos anexos.
Métrica
Custo por agendamento e por fechamento, devolvidos à Meta pela CAPI.
Por quê
Otimizar por evento de fundo ensina o algoritmo a buscar quem fecha, não quem só manda "oi".

Anexos

Material de apoio.

Usados nas aulas 02, 07 e 11. Identificadores de produção, contatos e chaves ficam fora deste material.

A

Kit nova clínica · CRM Mega Social Media

Passo a passo de instalação para um cliente novo, em cerca de 15 minutos.
Modelo clínica

Novo → Em atendimento → Agendou → Compareceu → Fechou (+ Nutrição, Perdido), com Agenda. Eventos: Agendou, Compareceu, Fechou.

Modelo escola

Novo lead → Em atendimento → Decidindo → Matriculou (+ Perdido), sem Agenda. Evento: só a matrícula.

Cada clínica tem o próprio Supabase (banco) e a própria Cloudflare (site), nas contas dela. Só o app da Meta "CRM Clinicas" é compartilhado. Nada de outro cliente vai junto.

O que pedir ao cliente

  • Um Gmail da clínica, para criar Supabase e Cloudflare em nome dela.
  • Nome da clínica e de quem será o administrador.
  • ID do pixel/conjunto de dados e token da API de Conversões, se já for enviar eventos.

  1. Supabase: criar o projeto

    supabase.com → entrar com o Gmail da clínica → New project (região São Paulo, plano Free). Guardar a senha do banco em lugar seguro.

  2. Banco

    SQL Editor → New query → colar o 1_banco.sql inteiro → Run. Deve aparecer "Banco do CRM criado".

  3. Usuário administrador

    Authentication → Users → Add user → Create new user. E-mail admin@SLUG.crm (ex.: admin@bella.crm; slug curto, minúsculo, sem espaço). O cliente digita a senha. Marcar Auto Confirm User. Depois: Sign In / Providers → desligar Allow new users to sign up.

  4. Configurar a clínica

    Preencher o bloco "PREENCHA" do 2_configurar_clinica.sql (nome, slug, admin, pixel, token, nomes dos eventos) → SQL Editor → Run. Pode rodar de novo para corrigir. Sem pixel/token agora, deixar ''. Escola: agendou '', compareceu '', fechou 'CRM_Matricula'; etapa com nome vazio não envia evento.

  5. Funções (Edge Functions)

    Deploy a new function → Via Editor, uma de cada vez, com estes nomes exatos:

    NomeArquivoVerify JWT
    admin-usuariosfuncoes/admin-usuarios.tsligado
    whatsapp-conectarfuncoes/whatsapp-conectar.jsdesligado
    whatsapp-webhookfuncoes/whatsapp-webhook.jsdesligado

    Secrets: WHATSAPP_VERIFY_TOKEN (texto aleatório; o gerador do passo 6 sugere um), META_APP_ID e META_APP_SECRET. Os valores do app são colados pelo Felipe. O mentorado nunca vê a chave secreta.

  6. Gerar o site

    Project Settings → API Keys: copiar a Project URL e a Publishable key (nunca a secret). No Terminal, na pasta site:

    python3 gerar_site.py --nome "Clínica Bella" --slug bella --modelo clinica --url https://XXXX.supabase.co --chave sb_publishable_XXXX
# escola:
python3 gerar_site.py --nome "Escola X" --slug escolax --modelo escola --url https://XXXX.supabase.co --chave sb_publishable_XXXX

    Sai o site-bella.zip.

  7. Cloudflare: publicar

    dash.cloudflare.com (Gmail da clínica) → Workers & Pages → Create → Pages → Upload assets → projeto crm-bella → enviar o zip → Deploy. Endereço: https://crm-bella.pages.dev

  8. App da Meta (uma vez por clínica)

    No app CRM Clinicas: adicionar https://crm-bella.pages.dev/ em Login do Facebook para Empresas → Domínios permitidos para o SDK do JavaScript, e crm-bella.pages.dev em Configurações → Básico → Domínios do app.

  9. Teste

    Entrar com o usuário admin → criar lead de teste → marcar "Agendou" → conferir CRM_Agendou no Gerenciador de Eventos (na escola, Matriculou → CRM_Matricula) → apagar o lead de teste.

  10. Entrega ao cliente

    • Configurações → Anúncios: os anúncios de WhatsApp aparecem sozinhos; é só dar nome.
    • Configurações → Usuários: criar a recepção.
    • Configurações → WhatsApp: "Conectar WhatsApp" (o celular lê o QR; o número não pode estar ligado a outro parceiro).
    • Opcional: importar planilha antiga.

B

Contexto do projeto CRM

O que o produto faz, como os eventos funcionam e as regras de trabalho.

O que é

CRM web para clínicas e escolas que recebe leads do WhatsApp automaticamente e envia eventos de funil para a Meta pela API de Conversões. Cada cliente tem Supabase (banco e funções) e Cloudflare Pages (site) nas próprias contas. Só o app da Meta é do Felipe.

Eventos no caso em produção

EventoQuandoValor
CRM_AgendouLead marcado como AgendouValor da avaliação (padrão R$ 300, editável)
CRM_CompareceuPaciente compareceu—
CRM_FechouFechou protocoloValor do protocolo; pagamento adicional entra como nova compra só com o valor novo

Os status "Agendou" e "Perdido" movem o lead de etapa automaticamente.

Estrutura do código

  • app/: site em React + Vite, build em arquivo único.
  • supabase/migrations/: histórico do banco.
  • supabase/functions/: admin-usuarios, whatsapp-conectar, whatsapp-webhook.
  • kit-nova-clinica/: o kit do Anexo A.

Regras de trabalho

  • SQL pelo SQL Editor do navegador.
  • Testar SQL num Postgres local antes de aplicar em produção.
  • Publicar função em produção só com autorização do Felipe.
  • Nunca digitar senha. Tokens e segredos só nos Secrets do Supabase, colados pelo Felipe.
  • Não mexer no número da plataforma nem nos eventos do pixel do site do cliente.
